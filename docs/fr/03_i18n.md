# 03 — Internationalisation

## Le principe

Un registre unique, `SUPPORTED_LOCALES` dans
`urlshortener/constants_and_globals.py`, est **la** source de vérité.
Rien d'autre ne décide quelles langues existent.

```python
SUPPORTED_LOCALES = {
    "en": {"name": "English",  "selectable": True,  "tier": 1},
    "fr": {"name": "Français", "selectable": True,  "tier": 1},
    "de": {"name": "Deutsch",  "selectable": True,  "tier": 2},
    "es": {"name": "Español",  "selectable": True,  "tier": 2},
    "it": {"name": "Italiano", "selectable": False, "tier": 2},
    ...
}
```

- `selectable` : la langue est-elle proposée aux visiteurs.
- `tier` : 1 = relue par un locuteur, 2 = traduite, 3 = déclarée.

Les 33 codes et les noms natifs sont **identiques à ceux d'AlirPunkto**,
délibérément : un catalogue peut passer d'un projet à l'autre tel quel.

Livrées ici : `en`, `fr`, `de`, `es`. Les autres sont déclarées mais pas
proposées — un basculement de booléen les active le jour où leur
catalogue arrive.

### Note de périmètre

L'Union européenne compte **24 langues officielles** pour 27 États
membres — l'allemand, le français et le néerlandais sont partagés par
plusieurs États. Le registre porte ces 24 langues, plus l'espéranto et
quelques voisines déjà présentes dans les catalogues AlirPunkto, soit 33
entrées.

## Ajouter une langue

Deux gestes, pas trois.

1. Passer `selectable` à `True` dans le registre.
2. Créer `urlshortener/locale/<code>/LC_MESSAGES/urlshortener.po` et le
   compiler.

```bash
# repartir du gabarit
mkdir -p urlshortener/locale/it/LC_MESSAGES
cp urlshortener/locale/urlshortener.pot \
   urlshortener/locale/it/LC_MESSAGES/urlshortener.po
# ... traduire ...
pybabel compile -D urlshortener -d urlshortener/locale -l it
pytest -q tests/test_i18n.py
```

Les tests refusent le contraire : `test_registry_and_disk_agree` exige
une bijection stricte entre les langues proposées et les répertoires
présents. Une langue proposée sans catalogue, c'est une page à moitié
vide servie à un visiteur ; une langue traduite mais jamais activée,
c'est du travail perdu. Les deux échouent.

## Mettre à jour les messages

Les `msgid` sont **symboliques** (`home_heading`, `error_url_scheme`),
jamais la phrase anglaise. Reformuler l'anglais n'invalide donc aucune
traduction.

Après ajout d'un message dans un gabarit ou dans `views.py` :

1. l'ajouter au `.pot` avec son commentaire `#. Default:` ;
2. l'ajouter à chaque `.po` ;
3. recompiler les quatre `.mo` ;
4. lancer `pytest tests/test_i18n.py`.

Quatre verrous couvrent cette chaîne :

- tout `msgid` du `.pot` est présent dans chaque `.po` ;
- tout `msgid` d'un `.po` est présent dans le `.mo` — vérifié en
  **lisant le binaire**, ce qui prouve la recompilation et pas une
  copie périmée ;
- toute raison de refus levée par `urlvalidation.py` a un message dans
  `views.ERROR_MESSAGES` ;
- les catalogues traduits ne sont pas des copies de l'anglais.

## Négociation

Du plus explicite au moins explicite :

1. `?_LOCALE_=fr` dans l'URL ;
2. le cookie `_LOCALE_` (posé par `GET /locale/fr`, `HttpOnly`,
   `SameSite=Lax`, un an) ;
3. `Accept-Language`, croisé avec les langues réellement proposées —
   `fr-BE` atteint le catalogue `fr` ;
4. l'anglais.

Seule une langue `selectable` est retournée : demander `it` aujourd'hui
retombe sur l'anglais plutôt que d'afficher une page vide.

Le sélecteur de langue n'est pas une redirection ouverte : `came_from`
est refusé s'il n'est pas un chemin local (`tests/test_views.py`).
