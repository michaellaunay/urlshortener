# 03 — Internationalisation

## The principle

One registry, `SUPPORTED_LOCALES` in
`urlshortener/constants_and_globals.py`, is **the** source of truth.
Nothing else decides which languages exist.

```python
SUPPORTED_LOCALES = {
    "en": {"name": "English",  "selectable": True,  "tier": 1},
    "fr": {"name": "Français", "selectable": True,  "tier": 1},
    "de": {"name": "Deutsch",  "selectable": True,  "tier": 2},
    "es": {"name": "Español",  "selectable": True,  "tier": 2},
    "it": {"name": "Italiano", "selectable": False, "tier": 2},
    ...
}
```

- `selectable`: is the language offered to visitors.
- `tier`: 1 = reviewed by a speaker, 2 = translated, 3 = declared.

The 33 codes and native names are **identical to AlirPunkto's**,
deliberately: a catalogue can move from one project to the other
verbatim.

Delivered here: `en`, `fr`, `de`, `es`. The others are declared but not
offered — flipping one boolean activates a language the day its
catalogue lands.

### A note on scope

The European Union has **24 official languages** for 27 member states —
German, French and Dutch are each shared by several states. The
registry carries those 24, plus Esperanto and a few neighbours already
present in the AlirPunkto catalogues, for 33 entries in all.

## Adding a language

Two gestures, not three.

1. Set `selectable` to `True` in the registry.
2. Create `urlshortener/locale/<code>/LC_MESSAGES/urlshortener.po` and
   compile it.

```bash
# start from the template
mkdir -p urlshortener/locale/it/LC_MESSAGES
cp urlshortener/locale/urlshortener.pot \
   urlshortener/locale/it/LC_MESSAGES/urlshortener.po
# ... translate ...
pybabel compile -D urlshortener -d urlshortener/locale -l it
pytest -q tests/test_i18n.py
```

The tests refuse anything else: `test_registry_and_disk_agree` demands
a strict bijection between the offered languages and the directories
present. A language offered without a catalogue is a half-empty page
served to a visitor; a language translated but never activated is
wasted work. Both fail.

## Updating messages

The `msgid` values are **symbolic** (`home_heading`,
`error_url_scheme`), never the English sentence. Rewording the English
therefore invalidates no translation.

After adding a message to a template or to `views.py`:

1. add it to the `.pot` with its `#. Default:` comment;
2. add it to every `.po`;
3. recompile the four `.mo` files;
4. run `pytest tests/test_i18n.py`.

Four locks cover that chain:

- every `.pot` msgid is present in every `.po`;
- every `.po` msgid is present in the `.mo` — verified by **reading the
  binary**, which proves recompilation rather than a stale copy;
- every refusal reason raised by `urlvalidation.py` has a message in
  `views.ERROR_MESSAGES`;
- translated catalogues are not copies of the English one.

## Negotiation

From most explicit to least:

1. `?_LOCALE_=fr` in the URL;
2. the `_LOCALE_` cookie (set by `GET /locale/fr`; `HttpOnly`,
   `SameSite=Lax`, one year);
3. `Accept-Language`, intersected with the languages actually offered —
   `fr-BE` reaches the `fr` catalogue;
4. English.

Only a `selectable` language is ever returned: asking for `it` today
falls back to English rather than rendering an empty page.

The language switcher is not an open redirect: `came_from` is refused
unless it is a local path (`tests/test_views.py`).
