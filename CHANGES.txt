Changelog
=========

2.0.1 (2026-08-22) — internal security audit
--------------------------------------------

Findings and fixes from ``docs/fr/audits/20260822_audit_securite_interne.md``.
One regression test per finding, in ``tests/test_audit_20260822.py``.

- **S-01 (high, fixed)** A target carrying non-ASCII characters was
  stored and served raw in ``Location:``. Waitress encodes the header
  block as latin-1, so such a link answered **500 on every visit, for
  ever** (Japanese, Cyrillic, emoji), or redirected to a MANGLED
  address (latin-1 range). Targets are now stored and served in their
  wire form: IDNA host, percent-encoded path, no double encoding. The
  redirect re-applies it, because rows imported verbatim from 2016
  never went through creation.
- **S-02 (medium, mitigated + accepted)** Imported 2016 codes are one
  to three characters and sequential, so the whole legacy corpus is
  walkable. Added an optional read limit on the JSON API
  (``urlshortener.throttle_max_reads``, 0 by default). Inherent to the
  2016 design; the redirect is never limited.
- **S-03 (medium, fixed)** ``import_legacy`` interpolated the file path
  into a SQLite URI raw, so a path containing ``?`` silently dropped
  ``mode=ro`` from the operator's rollback copy.
- **S-04 (medium, fixed)** The rate limiter's key is the client
  address; the dictionary had no ceiling, so a scan from many addresses
  grew it until the process died. Hard cap with eviction.
- **S-05 (low, fixed)** ``trusted_proxy_count`` is now explicit in
  ``production.ini``: adding a CDN without raising it would hand the
  rate-limiting key to the visitor.
- **S-06 (low, partly applied)** ``cap_drop: ALL`` added to the compose
  service. ``read_only`` documented but deliberately NOT enabled
  untested.
- **S-07 (low, fixed)** The derived ``var/runtime.ini`` may carry a
  database password and lands on the data volume; it is created 0600.
- **S-08 (low, documented exception)** PYSEC-2026-3447 hits setuptools
  81, fixed in 83 — but pyramid 2.1 pins ``setuptools<82``, so the bump
  is impossible without leaving pyramid 2.1. ``pip-audit`` carries one
  named, dated exception; every other advisory still fails the job.
- **S-09 (low, fixed)** The 404 page counted every link in the table,
  so an enumeration scan charged one aggregate per miss and the handler
  itself failed when the database was down.
- **S-11 (low, fixed)** The SQLite pragmas were attached to the
  SQLAlchemy ``Engine`` CLASS at import time, silently reconfiguring
  every other engine in the process. Attached to our engine instead.

Accepted risks, written down rather than fixed: the service is an open
redirector by design (S-12), ``GET /?url=`` writes and carries no CSRF
token (S-10, kept for 2016 clients), and no name is resolved at
creation time, so DNS rebinding is not covered (S-13).


2.0.0 (2026-08-22)
------------------

Complete rewrite of the 2016 Flask service (ecreall/urlshortener). The
public contract is preserved; everything under it changed.

Compatibility kept (locked by tests/test_legacy_compat.py)

- ``GET /?url=<target>`` still answers the same JSON object
  ``{"short_url", "code": "SUCCESS", "original_url"}``.
- ``POST /`` with a form field ``url`` still answers the HTML page.
- ``GET /<code>`` still answers 302 to the target.
- A submitted address with no scheme is still completed with ``http://``.
- The short-code alphabet is unchanged (digits, lowercase, uppercase),
  so every code minted since 2016 remains a legal code.

Compatibility broken, deliberately

- An unknown code now answers **404** instead of 200 with an error
  page. No monitor could previously tell a dead link from a live one.
- A refused URL answers **400** (and 503 / 429 where they apply)
  instead of 200 with ``code: ERROR``. The body shape is unchanged.
- ``Access-Control-Allow-Origin: *`` is no longer sent to everyone.
  Set ``urlshortener.cors_origins`` to restore it (``*`` is still
  expressible).
- The public base of the short links is configuration
  (``urlshortener.base_url``), not the hard-coded ``http://6li.eu/``.

Security

- SQL statements are parameterised. The 2016 code built INSERT and
  SELECT with ``.format()`` on user input.
- Target URLs are validated: scheme allowlist (http/https), no
  credentials in the authority, no control characters, hostname syntax
  checked, literal private/loopback/link-local addresses refused by
  default. ``javascript:``, ``data:`` and ``file:`` were accepted and
  redirected to before.
- Short codes are drawn from ``secrets`` instead of a sequential
  counter, so one code no longer discloses the next.
- Security headers on every response: CSP with ``frame-ancestors
  'none'``, ``X-Content-Type-Options``, ``X-Frame-Options``,
  ``Referrer-Policy: no-referrer`` on the redirect.
- No third-party asset: the 2016 page pulled Bootstrap and Font Awesome
  from maxcdn on every view.
- No IP address is stored. Rate limiting uses an in-memory window.

Added

- JSON API v1: ``POST /api/v1/shorten``, ``GET /api/v1/links/{code}``.
- ``GET /healthz`` with a real database round-trip, used by the
  container health check.
- Interface in English, French, German and Spanish, with a single
  locale registry (``SUPPORTED_LOCALES``) and the remaining EU official
  languages declared but not yet offered.
- Hit counting per link.
- ``tools/import_legacy``: imports the 2016 ``var/urls.db`` verbatim.
- Schema versioning with contiguous upgrade steps.
- Multi-stage Docker image (digest-pinned base, hash-checked lock,
  non-root, health check) and a compose file.
- 170 tests.

Changed

- Pyramid 2.1 + SQLAlchemy 2 + waitress, Python >= 3.11. The 2016
  requirements (Flask 0.10.1, Flask-Cors 2.1.2) no longer install, and
  ``flask.ext.cors`` has not been importable since Flask 0.11.
- Three hash-pinned dependency locks (runtime / test / quality).
